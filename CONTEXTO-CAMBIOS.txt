FLUJO DEL FORMULARIO DE PUBLICACION
-----------------------------------
- publicar.html contiene el formulario y una tarjeta de siguiente paso que se
  muestra despues de guardar correctamente. Las publicaciones ahora se guardan
  en Neon mediante POST /api/publicaciones.
- js/main.js comprime hasta tres fotos a un maximo de 800 px y las exporta
  como JPEG calidad 0.7 antes de enviarlas. Cada data URL se limita a 1 MB.
- La condicion operativa ofrece un enlace a intercambio.html; la condicion de
  reparacion recomienda un tecnico o taller local; la condicion no reutilizable
  ofrece un enlace a puntos-acopio.html.
- Publicar requiere una sesion activa; si expiro o falta, se redirige a
  login.html. El distrito se obtiene del perfil asociado a la sesion.

BUSQUEDA POR UBICACION EN PUNTOS DE ACOPIO
-----------------------------------------
- El boton "Usar mi ubicacion" de puntos-acopio.html solicita la posicion con

- Si se deniega el permiso o falla la ubicacion, se informa en pantalla y se

- Geolocation requiere un contexto seguro (HTTPS o localhost).
- Se probo el ordenamiento y las distancias desde el punto de la campana de
  Parque Kurt Beer, la denegacion del permiso sin alterar las tarjetas y la

AUTENTICACION CON NEON Y VERCEL
-------------------------------
- La autenticacion usa funciones serverless same-origin en api/ y Neon Postgres.
- package.json declara @neondatabase/serverless, bcryptjs y jsonwebtoken.
  db.js obtiene la conexion desde DATABASE_URL; no hay credenciales en el
  repositorio.
- schema.sql crea la tabla usuarios con id autogenerado, nombre, apellidos,
  distrito, email unico en minusculas y password_hash. Ejecutar su contenido
  en el SQL Editor de Neon antes de probar el registro.
- api/registro.js valida los datos, normaliza el correo, genera el hash con
  bcryptjs (coste 12), crea la cuenta y devuelve una cookie de sesion.
- api/login.js verifica credenciales sin revelar si el correo o la contraseña
  fueron incorrectos. api/logout.js invalida la cookie y api/me.js devuelve
  un perfil sin password_hash o user null cuando no hay sesion valida.
- La cookie JWT se llama piura_circular_session, dura siete dias y usa
  HttpOnly, SameSite=Lax y Secure en produccion. JWT_SECRET debe contener al
  menos 32 bytes. El token no se guarda en localStorage.
- En Vercel, configurar como variables de entorno DATABASE_URL (connection
  string de Neon) y JWT_SECRET (secreto aleatorio de al menos 32 bytes), para
  cada entorno que se vaya a usar. Generar un secreto con:
  node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"
  No copiar ese valor al repositorio ni compartirlo publicamente.
- Instalar dependencias con npm install. Aplicar schema.sql una sola vez en la
  base de Neon. En desarrollo local, usar Vercel CLI (vercel dev) con esas
  variables configuradas; abrir las paginas con un servidor estatico no ejecuta
  las funciones api/.
- Rutas: POST /api/registro, POST /api/login, POST /api/logout y GET /api/me.
  Los formularios de registro e inicio de sesion muestran errores devueltos por
  el API y redirigen a index.html al autenticarse.
- Los ocho menus consultan /api/me y cambian los enlaces de inicio/registro por
  "Cerrar sesion" cuando hay un usuario autenticado.
- Ejecutar npm test para validar los estados HTTP, la cookie, la duracion del
  JWT y la lectura de la sesion sin requerir una conexion real a Neon.
- La tabla usuarios guarda nombre, apellidos, distrito, email normalizado y
  hash de contraseña. El formulario de registro no publica la contraseña.

PUBLICACIONES EN NEON
---------------------
- schema.sql crea la tabla publicaciones con autor relacionado a usuarios,
  categoria, marca, antiguedad, descripcion, condicion, fotos JSONB y fecha.
  La descripcion esta limitada a 1000 caracteres y la tabla acepta hasta tres
  fotos por registro.
- api/publicaciones.js expone GET /api/publicaciones para listar publicaciones
  de mas recientes a mas antiguas, con autor (nombre e inicial del apellido),
  distrito, campos del equipo y fotos. No incluye el correo del usuario.
- GET /api/publicaciones?summary=1 devuelve conteos agregados para los
  indicadores, sin transferir registros individuales, descripciones ni fotos.
- POST /api/publicaciones requiere cookie de sesion valida, toma el distrito
  desde el perfil de Neon y valida categoria, descripcion, condicion y hasta
  tres imagenes JPEG en data URL (cada una hasta 1 MB).
- publicar.html reduce cada imagen en el navegador a un maximo de 800 px y la
  codifica como JPEG con calidad 0.7 antes del POST. Si la sesion no existe,
  redirige a login.html. Las publicaciones dejaron de guardarse en localStorage.
- intercambio.html carga las publicaciones desde la API y muestra solo las de
  condicion Operativo o Requiere reparacion. Los filtros y la busqueda se
  mantienen; las cuatro tarjetas de ejemplo solo se muestran cuando la API
  confirma que la base no tiene publicaciones.
- Los contadores de index.html y educacion.html obtienen los estados desde
  GET /api/publicaciones?summary=1. Los distritos siguen calculandose desde el
  catalogo RAEE local.
- Ejecutar schema.sql otra vez en Neon para crear la tabla de publicaciones y
  su indice antes de usar este flujo.

COMO ESTA ORGANIZADO EL MAPA DE RAEE
-----------------------------------
- puntos-acopio.html contiene los controles de filtro, el mapa y el contenedor
  vacio de resultados. La pagina incluye Leaflet y Leaflet.markercluster
  mediante CDN.
- assets/data/raee-points.json contiene la copia local de los puntos. El
  navegador la solicita desde js/main.js mediante fetch().
- js/main.js carga y valida el JSON, crea las tarjetas y los marcadores,
  rellena el filtro de departamentos y conecta los controles.
- css/styles.css define el diseno de los controles, las tarjetas, los grupos de
  marcadores y los ajustes responsive.
- Para agregar o actualizar ubicaciones, editar/regenerar el JSON y conservar
  las propiedades utilizadas por el JavaScript: name, address, district,
  province, department, hours, categories, system, lat y lng.
- categories es una lista de codigos numericos RAEE del 1 al 10.
- El JSON omite telefono, correo, nombre de contacto y enlaces de anexos.

IMPORTANTE SOBRE LA FUENTE DE DATOS
-----------------------------------
- La web utiliza una copia estatica; NO esta conectada en vivo a Google My Maps.
  Los cambios hechos en el mapa de Google no apareceran automaticamente aqui.
- La copia actual se consulto el 26 de octubre de 2026. La pagina tambien
  indica esta fecha y recomienda confirmar horarios y recepcion antes de ir.
- El mapa publico incluye poligonos de departamentos; para las tarjetas y pines
  se usan las ubicaciones puntuales del JSON.
- Las coordenadas y los datos de horarios provienen de la fuente y pueden ser
  inexactos o quedar desactualizados. No presentarlos como verificados.
- Para que fetch("assets/data/raee-points.json") funcione, abrir el proyecto
  mediante un servidor web (por ejemplo, Live Server), no como archivo file://.

MENSAJERIA ENTRE USUARIOS
-------------------------
- schema.sql crea las tablas conversaciones y mensajes, con sus columnas
  principales solicitadas, relaciones con usuarios/publicaciones y restricciones
  para evitar una conversación duplicada por publicación e interesado.
- api/conversaciones.js permite abrir o reutilizar una conversación por
  publicación y obtener la lista propia con título del equipo, otra persona,
  último mensaje y actividad. No devuelve correos.
- api/mensajes.js devuelve mensajes ordenados cronológicamente y permite enviar
  textos de 1 a 1000 caracteres. Ambas operaciones comprueban que el usuario
  autenticado participa en la conversación.
- mensajes.html ofrece la lista de conversaciones, el chat, el envío de
  mensajes y la sugerencia de puntos de acopio del departamento Piura.
- js/main.js inicia conversaciones desde las publicaciones reales de
  intercambio.html; las tarjetas de ejemplo conservan su aviso demostrativo.
  El chat consulta las conversaciones y mensajes cada cinco segundos mientras
  la pestaña está visible. Los nombres, direcciones y mensajes se agregan con
  textContent, sin insertar HTML recibido desde la API.
- Aplicar schema.sql en Neon para crear las nuevas tablas antes de usar el
  chat. Las rutas requieren la sesión configurada mediante JWT_SECRET y la
  conexión DATABASE_URL.
- Pruebas automatizadas cubren sesión requerida, validaciones de entrada,
  estructura de esquema y selectores del chat. No se confirmó la conexión a una
  base Neon real en este entorno.

NOTIFICACIONES Y MENU DE PERFIL
-------------------------------
- mensajes.leido es BOOLEAN NOT NULL DEFAULT FALSE. schema.sql también incluye
  ALTER TABLE ... ADD COLUMN IF NOT EXISTS para actualizar sin perder datos una
  tabla mensajes creada previamente.
- Al crear una conversación nueva, api/conversaciones.js inserta un primer
  mensaje automático del interesado con la categoría y marca del equipo. Si la
  conversación ya existía, no vuelve a insertar el saludo.
- GET /api/mensajes?resumen=1 cuenta los mensajes no leídos escritos por otra
  persona en conversaciones del usuario. GET /api/conversaciones incluye
  unreadCount para cada conversación.
- GET /api/mensajes?conversacion=ID devuelve los mensajes y marca como leídos
  los enviados por la otra persona. El total se actualiza al recargar la
  conversación o al consultar el resumen.
- El menú de perfil se construye en js/main.js desde el perfil de /api/me.
  Incluye inicial, nombre, correo, enlace a Mensajería e insignias; actualiza el
  total cada 15 segundos cuando la pestaña está visible y se cierra al hacer
  clic fuera o pulsar Escape.

PANEL INSTITUCIONAL
-------------------
- institucional.html verifica /api/me antes de mostrar el panel; sin sesión
  redirige a login.html y las cuentas que no sean entidades vuelven a index.html.
- El panel presenta los agregados de /api/institucional, gráficos por mes y
  distrito, gestión de puntos en un mapa Leaflet de Piura, cambio simulado de
  plan y descarga CSV local.
- GET /api/puntos?propios=1 requiere sesión de entidad y devuelve todos los

  El menú de perfil agrega Panel institucional únicamente para rol entidad.
